# Project Reporting

Use for recurring project or portfolio updates.

## Inputs

- Plan
- Current evidence
- Risks
- Audience

## Workflow

1. Compare current state with the agreed plan.
2. Lead with outcomes and material changes.
3. Separate risks, blockers, and decisions.
4. Assign confirmed owners and next review dates.

## Output

- Status report
- Risk summary
- Decision requests
- Next actions

## Boundaries

- Do not use traffic-light status without evidence.
- Do not hide uncertainty.
- Do not invent completion percentages.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
