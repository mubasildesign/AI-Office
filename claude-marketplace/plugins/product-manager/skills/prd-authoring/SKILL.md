# PRD Authoring

Use when a product direction is chosen and needs shared requirements.

## Inputs

- Approved problem
- Target users
- Constraints
- Success evidence

## Workflow

1. Define outcome, scope, and non-goals.
2. Describe primary flows and requirements.
3. Capture states, risks, and open decisions.
4. Write measurable acceptance signals.

## Output

- PRD
- Requirement list
- Open-decision log
- Acceptance signals

## Boundaries

- Do not disguise unresolved decisions as requirements.
- Do not dictate technical architecture.
- Keep scope traceable to the problem.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
