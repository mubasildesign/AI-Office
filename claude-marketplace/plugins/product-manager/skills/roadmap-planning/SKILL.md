# Roadmap Planning

Use when product work must be sequenced across a planning horizon.

## Inputs

- Product outcomes
- Prioritized opportunities
- Dependencies
- Planning horizon

## Workflow

1. Group work by outcome rather than feature list.
2. Sequence learning before irreversible investment.
3. Expose dependencies and capacity assumptions.
4. Define review points and change conditions.

## Output

- Outcome roadmap
- Dependency map
- Review cadence

## Boundaries

- Do not promise dates without team input.
- Do not turn discovery into guaranteed delivery.
- Preserve room for evidence.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
