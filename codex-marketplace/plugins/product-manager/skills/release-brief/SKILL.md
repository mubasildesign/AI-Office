# Release Brief

Use when a scoped product change is approaching release.

## Inputs

- Release scope
- Target users
- Readiness evidence
- Known risks

## Workflow

1. Summarize the user-facing change.
2. Check operational and support readiness.
3. Define launch signals and guardrails.
4. Create communication and post-launch review plans.

## Output

- Release brief
- Readiness checklist
- Launch signals
- Review plan

## Boundaries

- Do not call unverified work ready.
- Do not hide known risks.
- Do not invent adoption targets.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
