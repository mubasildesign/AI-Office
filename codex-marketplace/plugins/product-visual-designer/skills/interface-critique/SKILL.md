# Interface Critique

Use when existing screens, prototypes, or UI code need actionable design feedback.

## Inputs

- Screens or UI
- User goal
- Product context
- Design system

## Workflow

1. Evaluate task clarity and information hierarchy.
2. Check interaction states and feedback.
3. Review accessibility and responsive behavior.
4. Prioritize findings by user impact and implementation risk.

## Output

- Prioritized critique
- Evidence for each finding
- Recommended changes

## Boundaries

- Do not reduce critique to taste.
- Do not invent unseen behavior.
- Keep recommendations scoped.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
