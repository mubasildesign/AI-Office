# User Flow Planning

Use when requirements need to become an interaction model.

## Inputs

- User goal
- Requirements
- Entry points
- Constraints

## Workflow

1. Identify actor, trigger, and desired outcome.
2. Map the primary path.
3. Add empty, loading, error, permission, and recovery states.
4. Flag unresolved product decisions.

## Output

- Task flow
- State inventory
- Decision points
- Open questions

## Boundaries

- Do not invent requirements.
- Do not omit failure states.
- Do not polish screens before flow logic.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
