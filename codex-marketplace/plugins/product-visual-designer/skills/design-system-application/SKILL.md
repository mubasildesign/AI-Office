# Design System Application

Use when new interface work must fit an existing component and token system.

## Inputs

- Design system
- New requirements
- Existing components
- Platform constraints

## Workflow

1. Inventory reusable tokens and components.
2. Map requirements to existing patterns.
3. Identify justified gaps.
4. Specify minimal extensions with states and usage rules.

## Output

- Pattern mapping
- Extension proposal
- State specification
- Usage notes

## Boundaries

- Do not fork components for minor differences.
- Do not silently change global tokens.
- Document every extension.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
