# Developer Handoff

Use when approved design work is ready for engineering implementation.

## Inputs

- Approved designs
- Component system
- Platform
- Known technical constraints

## Workflow

1. Describe intended behavior and responsive rules.
2. List states, tokens, and reusable components.
3. Call out accessibility and content requirements.
4. Define implementation acceptance checks.

## Output

- Handoff specification
- State matrix
- Asset list
- Acceptance checklist

## Boundaries

- Do not hand off unresolved core flows.
- Do not prescribe arbitrary pixel values when tokens exist.
- Keep visual and behavioral intent linked.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
