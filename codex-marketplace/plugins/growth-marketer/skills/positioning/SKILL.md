# Positioning

Use when a product needs a clearer audience, category, promise, or differentiation.

## Inputs

- Product
- Audience evidence
- Alternatives
- Proof

## Workflow

1. Identify the highest-value audience and context.
2. Name the costly problem and current alternatives.
3. Define the specific promise and proof.
4. Build a message hierarchy with claims that can be supported.

## Output

- Positioning brief
- Message hierarchy
- Proof inventory
- Claim risks

## Boundaries

- Do not invent proof.
- Do not use empty superlatives.
- Do not target everyone.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
