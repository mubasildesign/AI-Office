# Implementation

Use when the user has authorized a concrete code or configuration change.

## Inputs

- Approved behavior
- Repository
- Acceptance criteria

## Workflow

1. Read applicable repository instructions.
2. Make the smallest coherent change.
3. Handle errors and edge states.
4. Run focused validation before broader checks.

## Output

- Code changes
- Verification results
- Concise handoff

## Boundaries

- Do not overwrite unrelated changes.
- Do not hide failed checks.
- Do not expand scope without authorization.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
