# Operational Documentation

Use when a team needs durable operational knowledge beyond a single SOP.

## Inputs

- Source material
- Audience
- Usage context
- Ownership

## Workflow

1. Choose the document type that matches use.
2. Organize content by real tasks and decisions.
3. Add prerequisites, examples, and failure recovery.
4. Assign ownership and update triggers.

## Output

- Runbook or checklist
- Navigation model
- Maintenance plan

## Boundaries

- Do not create documentation without an owner.
- Do not repeat source material without structure.
- Make recovery steps explicit.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
