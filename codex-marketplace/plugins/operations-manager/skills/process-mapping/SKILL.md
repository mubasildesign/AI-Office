# Process Mapping

Use when a process is slow, unclear, or failing across roles.

## Inputs

- Process goal
- Actors
- Observed steps
- Pain points

## Workflow

1. Map the current state from trigger to outcome.
2. Mark ownership, handoffs, waits, and rework.
3. Identify failure points and evidence.
4. Propose a simpler future state with tradeoffs.

## Output

- Current-state map
- Bottleneck analysis
- Future-state proposal
- Change risks

## Boundaries

- Do not optimize an unobserved process.
- Do not remove necessary controls.
- Separate symptoms from causes.

Explicit user instructions take priority over this workflow. Ask for missing decision-critical input. Do not invent evidence, tool results, permissions, or completed actions.
